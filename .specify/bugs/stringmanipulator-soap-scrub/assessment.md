# Bug Assessment: StringManipulatorTool default scrubs what SOAP accepts and misses what it rejects

- **Slug**: stringmanipulator-soap-scrub
- **Created**: 2026-11-21
- **Source**: https://github.com/nkdAgility/azure-devops-migration-tools/issues/3258 (host: github.com, allowlisted; read with `gh issue view`)
- **Verdict**: valid
- **Severity**: medium

## Report (verbatim or summarized)

Issue #3258 "StringManipulatorTool default pattern removes supplementary-plane letters, not just emoji". The default pattern `[\uD800-\uDBFF][\uDC00-\uDFFF]` removes every character outside the BMP, including Osage (`𐓏`) and CJK Extension B (`𠀀`), while BMP emoji such as `⌚` are kept. The issue proposes matching emoji explicitly, with tests.

Martin's rule (2026-11-20) replaces the issue's emoji framing: the default must scrub anything the SOAP API does not support, and nothing else.

## Symptom

With StringManipulatorTool enabled and no manipulators configured, String fields lose every non-BMP character (letters and emoji) and U+FE0F, all of which SOAP saves fine. A value holding U+FFFE, which SOAP rejects, is not scrubbed, so that work item fails and the run exits 1. Expected: remove only what SOAP cannot save.

## Reproduction

On `main`, test orgs, scratch projects `amte2e-3258-*`, which were deleted afterwards. Full detail is in `.specify/wkr/3258.md`.

1. Enable `StringManipulatorTool` with `Manipulators: []`. Seed a Bug with `Microsoft.VSTS.Build.FoundIn` = `A𐓏B 𠀀 W⌚ E😀`. Migrate. The target has `AB  W⌚ E`, the run exits 0, and the loss is silent.
2. Replace the default with a no-op manipulator and seed one Bug per character. SOAP saved U+104CF, U+1F600, U+231A and U+FE0F unchanged. U+FFFE failed the save after the retry limit, and the run exited 1.
3. Unit level: applying the default pattern with .NET `Regex.Replace` turns `A𐓏B` and `A𠀀B` into `AB`, and leaves `A⌚B` and `A￾B` unchanged.

DEL and C1 (U+007F–U+009F) couldn't be tested, because Azure DevOps Services REST refuses to seed them. Martin decided not to scrub them.

## Suspected Code Paths

- `src/MigrationTools/Tools/StringManipulatorTool.cs:85` (`AddDefaultManipulator`): the default pattern and its misleading description.
- `src/MigrationTools.Clients.TfsObjectModel/Processors/TfsWorkItemMigrationProcessor.cs:808-812`: the only caller. It runs for `FieldType.String` fields that differ between source and target.
- `TfsWorkItemMigrationProcessor.cs:767`: `System.Title` is copied directly and never passes through the tool (Q-2).

## Root Cause Hypothesis

The default equates "surrogate pair" with "emoji". It doesn't target the characters that actually break a SOAP (XML 1.0) payload: C0 controls other than tab, LF and CR; lone surrogates; and U+FFFE/U+FFFF. So it over-scrubs valid text and under-scrubs the one class the test org proved fatal. Confidence: high.

## Proposed Remediation

**Preferred**: replace the default pattern with
`[\x00-\x08\x0B\x0C\x0E-\x1F]|[\uD800-\uDBFF](?![\uDC00-\uDFFF])|(?<![\uD800-\uDBFF])[\uDC00-\uDFFF]|[￾￿]`.
DEL and C1 are no longer scrubbed (Martin, Q-6). Update `Description` to say it removes characters the SOAP API cannot save. The pattern stays a plain regex, so users can copy it into their own config.

**Alternatives**:
- Filter by rune in code instead of a regex. That is more exact, but it adds a code path and can't be copied into config.

Martin also decided (2026-11-21): route `System.Title` through the tool (Q-2), and remove the ASCII-only manipulator from the shipped configs so the new default applies (Q-3).

- `configuration-default.json`, `configuration-classic.json`
- `tools/e2e/scenarios/stringmanip-3258/**`
- `src/MigrationTools/Tools/StringManipulatorTool.cs`

- `docs/content/docs/reference/tools/stringmanipulatortool/index.md`

**Tests to add or update**:
- Unchanged: `A𐓏B`, `A𠀀B`, `A😀B`, `A⌚B`, `A❤️B`, `café`, tab/LF/CR.
- Reduced to `AB`: U+0001, U+000B, U+001F, U+FFFE, U+FFFF, a lone high surrogate and a lone low surrogate.
- A user-supplied manipulator replaces the default.

## Risks & Considerations

- This changes migrated output for anyone on the built-in default: emoji and non-BMP letters are now kept (Q-5).
- Removing the ASCII-only manipulator from `configuration-default.json` and `configuration-classic.json` means new users keep non-ASCII text (Q-3).
- Routing Title through the tool means a Title is scrubbed like any other String field; with the new default only SOAP-invalid characters are removed (Q-2).
